# Feature specs

One file per feature, named `feature-NN-short-name.md`, keyed to the feature log in
`docs/PROJECT_MEMORY.md` §5.

The spec is written **before** the implementation and in a **separate session**
(playbook §2.5). Mixing spec and implementation in one session produces code that
confirms the spec rather than testing it.

Status progresses: `Specified` → `In progress` → `Done`. A feature is `Done` only when
the Definition of Done in `CLAUDE.md` is satisfied — including the test output pasted
into the session that closed it.

Start from `_TEMPLATE.md`.
